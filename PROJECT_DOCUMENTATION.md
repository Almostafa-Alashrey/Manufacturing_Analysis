## How to use this file

1. Pull the latest `main` and create your own branch: `git checkout -b docs/<your-name>-<section>`.
2. Write your owner name in the **Owner** line of your section and change the **Status**.
3. Write your content under `✍️ WRITE HERE`, then **delete the marker line** (images go in `docs/images/` and are linked with `![caption](images/file.png)`).
4. Do not edit other people's sections. This avoids merge conflicts.
5. Commit with a clear message, for example `docs(4.5): add ER diagram`, push, and open a Pull Request.
6. The PDF is built from this file: run `python docs/build_pdf.py` (needs `pip install reportlab`).

## Appendix A: Machine Learning Model and Streamlit App

**Owner:** _TBD_ · **Status:** 🟨 (draft written, review needed)

### A.1 Problem
Estimate the health of each machine from its sensor readings, so maintenance can start with the machines that need it most.

### A.2 Data
Cleaned dataset: 100,000 readings, 5,000 machines (about 20 readings each), 72 columns. Failures are rare (1.47%).

### A.3 Approach
- **Model:** Linear Regression (numbers scaled, text columns one-hot encoded), target `machine_health_score`. LightGBM was tested as a comparison.
- **Validation:** `GroupKFold` (5 folds) by `machine_id`, so a machine is never in training and testing at the same time.
- **Removed columns:** IDs and dates, failure columns, and the health/anomaly scores (to avoid leakage).
- **Status levels:** from the predicted health of the training machines (lowest 10% = Needs attention, next 20% = Monitor).

### A.4 Results
| Model | R² | MAE (points) |
|---|---|---|
| Baseline (average) | 0 | 4.15 |
| **Linear Regression (final model)** | 0.802 | 1.87 |
| LightGBM | 0.800 | 1.88 |

Both models give the same result, so the simpler and more explainable model (Linear Regression) was chosen.

### A.5 Predicting machine failure (what we tried)
| Approach | PR-AUC | ROC-AUC |
|---|---|---|
| Baseline (failure rate) | 0.0147 | 0.500 |
| Raw sensors | 0.0151 | 0.500 |
| Raw + derived scores | 0.0148 | 0.498 |
| History + ratio features | 0.0144 | 0.495 |
| Predict the next reading | 0.0144 | 0.493 |

All results are equal to random guessing. In the data, 25.6% of the machines have at least one failure, and 25.7% is expected if failures are random. The failure type looks predictable (about 90%), but it is decided by the weakest `*_health` column, so it is leakage.

### A.6 Streamlit app
Upload a CSV/Parquet file, see the fleet status, the machines that need attention first, the weakest part of each machine, and download an HTML report. Run with `streamlit run app.py`.

### A.7 Limitations
The dataset looks synthetic, and the health columns are almost constant inside each machine, so the model estimates long-term health, not sudden changes.
